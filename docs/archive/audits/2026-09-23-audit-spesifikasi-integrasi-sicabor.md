# Audit implementasi spesifikasi integrasi KOK–SICABOR

**Tanggal:** 23 September 2026  
**Basis source:** `f97db01` (`main`)  
**Ruang lingkup:** enam desain integrasi bertanggal 19–23 September 2026, implementasi Flutter, mock server lokal, test, dan [kontrak API KOK SICABOR](../../api/api-kok-sicabor.md).

## Cara membaca hasil

Kontrak API adalah acuan perilaku server; desain di `docs/archive/specs` adalah keputusan historis. **Terimplementasi** berarti jalur kode dan test yang relevan ditemukan, bukan sudah cocok dengan server SICABOR yang sebenarnya. **Sebagian** berarti alur utama ada tetapi satu atau lebih kriteria desain/kontrak belum terpenuhi. Audit ini membandingkan source dan test, bukan melakukan pengujian pada API resmi atau perangkat Android.

`flutter analyze --no-pub` selesai tanpa issue. `flutter test --no-pub --reporter compact` selesai dengan **739 test lulus dan 1 dilewati**. Hasil itu belum membuktikan perilaku skenario yang belum memiliki test, kecocokan dengan data server asli, atau kesiapan rilis.

## Temuan yang perlu ditindaklanjuti

### Prioritas 1 — sebelum uji penerimaan dengan server resmi

1. **401/403 dari sesi lama bisa mengeluarkan pengguna yang baru login.** [Interceptor](../../../lib/core/network/auth_session_interceptor.dart) (baris 32–44) memanggil logout tanpa membandingkan token/generasi permintaan dengan sesi aktif; callback [AuthController](../../../lib/core/auth/presentation/auth_controller.dart) (baris 190–192) menutup sesi yang sedang aktif. Uji permintaan akun A yang baru gagal setelah akun B berhasil login, lalu abaikan respons A.
2. **Mock menerima token Bearer yang tidak pernah diterbitkan.** [MockData](../../../scripts/mock_server/mock_data.dart) (baris 1471–1493) mencari akun dari pola teks token jika token tidak ada pada daftar sesi. [Router](../../../scripts/mock_server/sicabor_mock_server.dart) (baris 188–209) mempercayai hasil itu; token tidak dikenal juga mendapat `403 MEMBER_NOT_FOUND`, sementara kontrak meminta `401 INVALID_TOKEN`. Mock yang dapat diakses jaringan lokal ini tidak cocok dipakai menguji batas autentikasi sampai fallback dihapus dan token diverifikasi dari daftar penerbitan.
3. **Mock tidak mensimulasikan kedaluwarsa token 24 jam.** Peta sesi di `mock_data.dart` hanya menyimpan akun, tanpa waktu terbit/kedaluwarsa. Tambahkan jam yang dapat dikendalikan test, `401` untuk token kedaluwarsa, serta uji bahwa restart server tidak membuat token lama sah kembali.
4. **Respons gagal lintas sesi masih bisa mengisi state daftar baru.** Jalur sukses membandingkan `DataRequestContext`, tetapi blok `catch` pada [Cabor](../../../lib/data/providers/cabor_providers.dart) (baris 190, 225), [Atlet](../../../lib/data/providers/athlete_providers.dart) (baris 237, 277), dan [Klub](../../../lib/data/providers/club_providers.dart) (baris 224, 262) hanya memeriksa generation counter. Setelah ganti akun, kegagalan permintaan akun lama dapat muncul sebagai galat akun baru. Terapkan guard konteks yang sama pada keenam jalur error.
5. **Penyimpangan respons `/profile` belum ditolak secara aman saat auth/restore.** [DTO profil](../../../lib/core/auth/data/dto/sicabor_profile_response.dart) (baris 218–230, 273–282) mengisi `member`/`scope` yang hilang dengan nilai kosong atau nol; [repository auth](../../../lib/core/auth/data/remote_auth_repository.dart) (baris 88–108, 137–153) hanya memeriksa `success`. Respons `success:true` yang tidak lengkap bisa membuat sesi dengan identitas atau kecamatan salah. Validasi field wajib dan peran dari profil sebelum menyimpan sesi.
6. **Permintaan auth belum memakai timeout konfigurasi.** [Composition](../../../lib/core/composition/app_composition.dart) (baris 100–117) membuat `Dio()` biasa untuk login dan restore, sedangkan timeout hanya diterapkan ke `ApiClient`. Saat jaringan menggantung, alur login/pemulihan sesi tidak punya batas waktu yang sama. Terapkan timeout konfigurasi juga pada client auth.

### Prioritas 2 — kebenaran data dan pengalaman pengguna

7. **Pesan otorisasi khusus hilang.** `403 NO_SUBDISTRICT` dengan benar tidak logout, tetapi [Profil](../../../lib/features/profile_page.dart) (baris 147–157) dan [Cabor](../../../lib/features/sports_page.dart) (baris 140–163) menampilkan galat umum dan retry. Kontrak meminta `message` server ditampilkan tanpa retry. Untuk `MEMBER_INACTIVE`, kode/pesan dari interceptor juga tidak diteruskan ke [state signed-out](../../../lib/core/auth/presentation/auth_controller.dart) (baris 190–192, 881–888), padahal desain meminta alasan yang jelas.
8. **Beranda salah melabeli dua angka cabor.** [HomePage](../../../lib/features/home_page.dart) (baris 525–526) menampilkan `totalCaborFromClub` sebagai “klub” dan `totalCaborFromAthlete` sebagai “atlet”. Menurut [kontrak](../../api/api-kok-sicabor.md), keduanya adalah jumlah **cabor** yang memiliki klub/atlet, bukan jumlah klub/atlet. Gunakan label “cabor dengan klub” dan “cabor dengan atlet”.
9. **Ringkasan Cabor memberi kesan daftar lengkap/aktif.** [SportsPage](../../../lib/features/sports_page.dart) (baris 66–75, 288–355) mengurutkan grafik dari item yang sudah dimuat saja, padahal halaman pertama API hanya 25 cabor dalam urutan nama; lima tertinggi bisa berubah setelah scroll. Judul “Cabang Olahraga Aktif” juga memakai total tanpa filter status aktif. Tampilkan cakupan grafik secara jujur atau ambil seluruh data yang diperlukan untuk peringkat.
10. **Waktu “Terakhir Dimuat” belum mewakili waktu pengambilan data.** [HomePage](../../../lib/features/home_page.dart) (baris 346–380) memakai `DateTime.now()` setiap build remote lalu memberi label WIB. Rebuild tanpa request baru dapat memajukan waktunya, dan zona waktu perangkat belum tentu WIB. Simpan waktu saat request berhasil atau hilangkan klaim waktu tersebut.
11. **Pencarian/filter dapat menampilkan hasil yang tidak sesuai.** Pada tab Atlet, tombol hapus teks [tidak membatalkan debounce](../../../lib/features/sport_detail/sport_detail_page.dart) (baris 1398–1447); query lama bisa kembali setelah kolom kosong. [Controller atlet](../../../lib/data/providers/athlete_providers.dart) (baris 207–241) mempertahankan item lama saat filter baru gagal, sedangkan UI hanya menampilkan galat bila daftar kosong (baris 1546–1551). Pola serupa ada pada daftar Cabor. Pastikan timer dibatalkan dan tampilkan galat/stale-state yang eksplisit.
12. **Detail Klub belum memenuhi dua keadaan data dan satu aksi.** [Tab Atlet Klub](../../../lib/features/club_detail/club_detail_page.dart) (baris 1489–1495) membandingkan total klub lintas kecamatan dengan `meta.total` yang ikut berubah karena pencarian/jenis kelamin, bahkan bisa menulis “0” saat loading. [Kepengurusan](../../../lib/features/club_detail/club_detail_page.dart) (baris 1019–1031) mengabaikan `dataAvailable:false`. Tombol [Berkas SK](../../../lib/features/club_detail/club_detail_page.dart) (baris 671–699) hanya menyalin tautan, sedangkan desain 4.1 meminta membukanya di browser. Pisahkan jumlah lokal tanpa filter dari jumlah hasil filter, tampilkan “Belum tercatat di sistem” bila data tidak tersedia, dan selaraskan aksi SK dengan desain.
13. **Kartu atlet dan tombol kontak belum sesuai kegunaannya.** [Kartu remote](../../../lib/features/sport_detail/sport_detail_page.dart) (baris 1672–1734) tidak menampilkan kode/status yang diminta desain, sehingga nama sama sulit dibedakan. Di [detail atlet](../../../lib/features/athlete_detail/athlete_detail_page.dart) (baris 823–926), “Hubungi pengurus klub” hanya membuka nama/kode klub tanpa sarana menghubungi; ubah label menjadi info klub atau hubungkan ke detail klub yang memiliki kontak.
14. **Konten non-JSON belum dikenali sebagai salah URL.** [ApiClient](../../../lib/core/network/api_client.dart) (baris 59–73) dan remote service langsung mengolah `response.data` sebagai Map; [auth repository](../../../lib/core/auth/data/remote_auth_repository.dart) (baris 48–55, 83–88) juga tidak memeriksa Content-Type. HTML dari salah path dapat menjadi cast/parse error alih-alih pesan konfigurasi yang dirancang dalam spesifikasi Beranda+Cabor.

### Kejelasan dokumentasi dan batas mock

- [Panduan mock server](../../../scripts/mock_server/README.md) (baris 86, 100) memberi contoh `DATA_MODE=demo`. Perintah itu menguji login remote tetapi **data Beranda/Cabor/Atlet/Klub tetap berasal dari demo lokal**. Untuk uji integrasi HTTP mock, contoh harus memakai `DATA_MODE=remote` dan diuji pada target Android yang dimaksud.
- Desain mock menyebut “password global SICABOR” yang berlaku pada akun sah, sedangkan source hanya membuktikan penggunaan nilai itu oleh mock (`mock_data.dart`, baris 292–293 dan 1466–1468). **Asal dan keberlakuannya pada server resmi tidak dapat dipastikan dari repo.** Konfirmasi dengan pemilik backend tanpa mengulang nilainya dalam laporan. Jika kredensial itu nyata, cabut/rotasi dan keluarkan dari dokumentasi, log startup, serta riwayat publik; jika hanya fixture, beri label tegas “khusus mock”.
- [Status proyek](../../project-status.md) sebelumnya menyebut opsi sort Klub lama dan “740 test passing”; keduanya tidak sesuai source/hasil verifikasi saat audit. Desain mock historis menulis port default 8080, sedangkan CLI dan README saat ini memakai 8088; perubahan port ini bukan cacat integrasi. Desain menyarankan pencatatan auth header di log, tetapi implementasi tidak mencetaknya; ini penyimpangan yang lebih aman dan patut dipertahankan.

## Urutan kerja yang disarankan

1. **Milestone 5.1 — integritas sesi dan kontrak error:** perbaiki temuan 1, 4–7, 14 dengan test respons akun lama, penolakan lama, profil tidak lengkap, timeout, dan `NO_SUBDISTRICT`/`MEMBER_INACTIVE`.
2. **Milestone 5.2 — ketepatan tampilan dan mock:** perbaiki temuan 2–3, 8–13; jalankan aplikasi dengan `AUTH_MODE=remote` **dan** `DATA_MODE=remote` terhadap mock server. Test harus mencakup paging lebih dari 25 item, dua kecamatan, dan keadaan data personel kosong/parsial.
3. **Milestone 6 — validasi API resmi:** setelah tim SICABOR menyediakan URL HTTPS dan akun uji yang diizinkan, cocokkan request/response nyata untuk login, `/profile`, daftar/detail Cabor–Klub–Atlet, filter, paging, 401/403/404, dan perubahan kecamatan. Catat setiap perbedaan kontrak beserta contoh respons yang sudah disamarkan. Uji juga pada Android fisik/emulator.
4. **Tahap rilis:** setelah integrasi resmi stabil, siapkan signing release, AAB, identitas aplikasi, kebijakan privasi/data safety, dan pengujian perangkat untuk Play Store. Endpoint official/pelatih sudah tercantum di kontrak tetapi datanya saat ini belum tersedia; pengembangan layar lanjutan menunggu kebutuhan data yang benar-benar ada.

**Batas keputusan:** audit ini tidak menyatakan API resmi telah tersambung atau aplikasi siap Play Store. Tidak ada perubahan kode aplikasi dalam audit ini.
